# Statistics validation

Generated by `tools/coverage.py` on 2026-11-14 with 2000 simulated series per row (half with a true trend of +0.2 per decade, half with none), run through the website's own `stats.js`. Noise standard deviation 0.3.

| Scenario | 95% interval contains the true trend: plain | adjusted (site) | False alarms, Mann-Kendall: plain | adjusted (site) | Real trend detected (site) |
|---|---|---|---|---|---|
| Yearly, 45 years, independent noise | 94.8% | 95.6% | 5.0% | 3.7% | 99.8% |
| Yearly, 45 years, year-to-year memory r = 0.3 | 84.8% | 94.4% | 14.8% | 7.2% | 95.0% |
| Monthly, 540 months, memory r = 0.6 | 68.0% | 94.7% | 28.8% | 5.2% | 100.0% |

Targets: about 95% coverage and about 5% false alarms.

The site adjusts both tests for year-to-year memory (lag-1 autocorrelation, effective sample size). Without that adjustment, data with memory gives intervals that are too narrow and too many false alarms; with it, both stay near their targets.

`tools/validate_stats.py` separately checks every number stats.js reports against SciPy (`linregress`, `theilslopes`, `t`, `norm`) and the formulas in the Methods section.
